# Types Package (`com.coderhino.types`)

Shared value types used across the entire application. Everything here is a record, sealed interface, or enum — immutable by design, no behavior beyond data access.

## Top-Level Types

### `Message` (sealed interface)

The central conversation type. Models the full dialogue between user, assistant, and tools.

```
Message (sealed)
├── UserMessage(String content)
├── AssistantMessage(String content)
├── AssistantToolUseMessage(String content, String toolName, String toolUseId, String assistantMessageId)
├── SystemMessage(String content)
└── ToolResultMessage(String content, String toolName, String toolUseId, String sourceAssistantMessageId)
```

- `type()` returns a string discriminator: `"user"`, `"assistant"`, `"assistant_tool_use"`, `"system"`, `"tool_result"`.
- `AssistantToolUseMessage` has a 3-arg constructor that sets `assistantMessageId` to null.
- `ToolResultMessage` has 2-arg and 3-arg convenience constructors.

**`Message.Envelope`** — wraps any `Message` for persistence:
- `uuid` — unique envelope ID
- `parentUuid` — links to the preceding envelope (conversation chain)
- `timestamp` — `Instant` when created
- `message` — the payload

Envelopes are serialized as JSONL (one per line) by `SessionStore`.

### `PermissionMode` (enum)

Controls how tool permission checks behave:

| Mode | Behavior |
|------|----------|
| `DEFAULT` | Prompt user for sensitive operations |
| `PLAN` | Restricted, limited permissions |
| `BYPASS` | Allow everything, skip all checks |
| `AUTO` | Auto-approve based on heuristics |
| `DONT_ASK` | Never prompt; auto-deny if not clearly safe |
| `ACCEPT_EDITS` | Auto-accept file edits, ask for destructive ops |

### `PermissionResult` (sealed interface)

Simple tri-state result from permission checking:

```
PermissionResult (sealed)
├── Allow()           → allowed() = true
├── Ask(String reason) → allowed() = false
└── Deny(String reason) → allowed() = false
```

Static factory methods: `PermissionResult.allow()`, `PermissionResult.ask(reason)`, `PermissionResult.deny(reason)`.

### `ToolInputSchema` (record)

Describes a tool's expected input shape as a JSON Schema object.

- `ToolInputSchema.object(properties)` — creates a schema with `type: "object"` and an immutable copy of the properties map.

### `CompactBoundary` (record)

Configures conversation compaction limits:

| Field | Purpose |
|-------|---------|
| `maxTokens` | Token count that triggers compaction |
| `targetTokens` | Token count to compact down to |
| `maxMessages` | Message count limit |

Predefined profiles:
- `CompactBoundary.conservative()` — 50K/40K tokens, 50 messages
- `CompactBoundary.moderate()` — 40K/30K tokens, 40 messages
- `CompactBoundary.aggressive()` — 30K/20K tokens, 30 messages

Helper methods: `exceedsMax(tokenCount)`, `meetsTarget(tokenCount)`.

## Sub-Package: `oauth`

OAuth authentication types for the Anthropic API.

### `OAuthAccount` (record)

| Field | Description |
|-------|-------------|
| `uuid` | Account ID |
| `emailAddress` | User email |
| `organizationUuid` | Organization ID |

### `OAuthConfig` (record)

Holds all OAuth endpoint URLs and client configuration. The production configuration is available as `OAuthConfig.PROD` (or `OAuthConfig.getDefault()`).

Key fields: `baseApiUrl`, `tokenUrl`, `apiKeyUrl`, `clientId`, `mcpProxyUrl`.

### `OAuthTokens` (record)

| Field | Description |
|-------|-------------|
| `accessToken` | Bearer token |
| `refreshToken` | Refresh token |
| `expiresAt` | Expiry epoch millis |
| `scopes` | Granted scopes (e.g. `"user:inference"`) |
| `subscriptionType` | Subscription tier |
| `rateLimitTier` | Rate limit classification |
| `tokenAccount` | Associated `OAuthAccount` |

- `isExpired()` — checks expiry with a 5-minute buffer.
- `hasInferenceScope()` — checks for `"user:inference"` scope.

### `PkcePair` (record)

PKCE (Proof Key for Code Exchange) parameters for OAuth flow:
- `codeVerifier` — random string generated by client
- `codeChallenge` — SHA-256 hash of verifier sent to auth server

## Sub-Package: `permissions`

Rich permission evaluation types used by the permission checking system.

### `PermissionContext` (record)

Input to permission evaluation — captures the full context of a permission check:

| Field | Description |
|-------|-------------|
| `toolName` | Which tool is requesting permission |
| `toolArgs` | Tool arguments map |
| `mode` | Current `PermissionMode` |
| `userId` | Optional user identifier |
| `workingDirectory` | Current working directory |
| `timestamp` | When the check was requested |

### `PermissionDecision` (record)

Result of evaluating a single permission rule:

| Field | Description |
|-------|-------------|
| `allowed` | Whether permission was granted |
| `reason` | `PermissionReason` explaining why |
| `mode` | `PermissionMode` at evaluation time |
| `matchedRuleId` | ID of the rule that matched (nullable) |
| `evaluatedAt` | `Instant` of evaluation |

### `PermissionReason` (sealed interface)

Explains why a decision was made:

```
PermissionReason (sealed)
├── Allowed(String message)
├── Denied(String message)
├── Ask(String message)
├── Bypassed(String message)
├── RuleMatch(String message, String matchedRuleId)  → ruleId() = Optional.of(matchedRuleId)
└── DefaultDeny(String message)
```

All variants except `RuleMatch` return `Optional.empty()` for `ruleId()`.

### `PermissionRule` (sealed interface)

Evaluatable rules that produce `PermissionDecision`s:

```
PermissionRule (sealed)
├── ToolNameRule(id, toolName, allow)     — exact tool name match
├── PatternRule(id, toolNamePattern, allow) — regex pattern match
├── AlwaysAllowRule(id)                    — always returns allow
└── AlwaysDenyRule(id)                     — always returns deny
```

- Each rule's `evaluate(context)` returns a `PermissionDecision` if it matches, or `null` if it doesn't.
- `PermissionRule.evaluateAll(rules, context)` iterates rules in order, returning the first match (first-match-wins).
- Static factories: `allowTool(id, name)`, `denyTool(id, name)`.

### `PermissionUpdate` (record)

Records a permission state change event:

| Field | Description |
|-------|-------------|
| `toolName` | Tool that was checked |
| `allowed` | Whether it was permitted |
| `matchedRuleId` | Rule that triggered the decision (nullable) |
| `timestamp` | When the update occurred |
| `metadata` | Additional key-value data |

## Design Principles

1. **Immutability** — Every type is a Java record. No mutable state.
2. **Sealed hierarchies** — `Message`, `PermissionResult`, `PermissionReason`, `PermissionRule` use sealed interfaces for exhaustive pattern matching.
3. **No business logic** — Types are pure data carriers. The only methods are accessors, simple predicates (`isExpired`, `exceedsMax`), and convenience constructors.
4. **Nullable fields documented via `Optional`** — Where nullability is meaningful (userId, matchedRuleId), `Optional` is used in return types or record fields.
